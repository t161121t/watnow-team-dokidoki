## 1. プロダクト概要

### 1.1 名称

**秘密オークション（仮）**（正式名称は未定。当面この表記でよい）

### 1.2 一文サマリ

仲のいい友達グループで、公開してよい「秘密」をオークション形式でやり取りし、意外な一面を知るコミュニケーションゲーム（PWA）。

### 1.3 課題

仲が良くても、意外な過去・趣味・エピソードを話すきっかけが少ない。

### 1.4 提供価値

- 知らなかった一面を知るきっかけ
- 普段生まれない会話
- グループ交流の深化
- ゲーム感覚の思い出づくり
- チャレンジ経由で新しい行動を促す

### 1.5 対象ユーザー

- プライマリ: 少人数の仲のいい友達グループ（学生〜若年層を想定した小規模チーム開発前提）
- 非対象（明示）: 見知らぬ人同士のマッチング、センシティブ情報の強制開示

### 1.6 コア体験ループ

```text
グループ参加
  → 秘密を登録（登録 ≠ 出品）
  → ミニゲーム/チャレンジ等でポイント獲得（グループ財布）
  → 出品 → 開催待ち → 競り（ディーラー進行）
  → 落札者が秘密を閲覧
```

ショップ（固定価格の即時購入）は**設けない**。秘密の獲得はオークションのみ。

## 3. 不変条件（プロダクト制約）

1. **グループ完全分離**: ポイント・秘密・オークションはグループ単位で独立。横断合算・共有なし
2. **本人が公開してよい秘密のみ**扱う
3. 落札後に閲覧可能になった秘密は、出品者が事後的に非公開へ戻せない（公平性）
4. ショップは廃止（実装しない）

## 4. 役割

| 役割 | 説明 |
| --- | --- |
| 入札者 | ポイントで入札し、落札すれば秘密を閲覧できる |
| 出品者 | 秘密を登録・出品し、出品・落札に応じてポイントを得る |
| 主催者（ディーラー） | 競りごとにランダム選抜。進行役。当該競りでは入札不可 |

1 競りにおいて同一ユーザーが複数役割を兼ねない（出品者 ≠ ディーラー、ディーラーは入札不可）。  
**確定**: 出品者は**自出品への入札不可**。

詳細は `オークションルール.md` §1–4。

## 8. スコープ総覧

### 8.1 MVP（Phase 1）で成立させたいこと

1. アカウント + グループ（作成/参加/切替/幹事）
2. 秘密の登録・出品・競り・落札閲覧（ディーラー付き、ショップなし）
3. グループ完全分離のポイント（履歴、マイナス残高許可、入札は残高内のみ）
4. ミニゲーム/チャレンジの**機能枠**（提供コンテンツは未定でも、グループ紐づけ付与の器は必要）
5. PWA としての基本利用（インストール案内は TRD / 技術選定に準拠）

### 8.2 Phase 2 の見通し

- 通知設定・Web Push 本格運用
- 秘密の複数グループ公開
- AI validation（無料枠で MVP に入れなかった場合の本採用）
- E2E・lint 厳格化などの周辺品質（`技術選定.md` Phase 2）
- 称号・実績、ウォッチリスト等の拡張 UX
- システム提供ミニゲーム/チャレンジ内容の拡充
- P1–P12 の運用で見えたバランス調整

### 8.3 非目標（今はやらない）

- ネイティブアプリ
- ショップ
- グループ間ポイント移動
- 見知らぬ人向け SNS 化
- KPI ダッシュボード（KPI 自体が未設定）
