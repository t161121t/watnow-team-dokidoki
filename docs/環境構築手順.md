# 環境構築手順

Windows と macOS のどちらでも、この手順で同じ開発環境を用意できます。初めての人は、コマンドを上から 1 行ずつ実行してください。

この手順では、Windows は **PowerShell**、macOS は **ターミナル**を使います。Windows では PowerShell・WSL・Git Bash を途中で混ぜないでください。OS の指定がないコマンドは、どちらでも同じです。

## 完了の目安

次の状態になれば環境構築は完了です。

- `pnpm env:check` ですべて `[ok]` と表示される
- `pnpm verify` がエラーなく終了する
- `pnpm dev` の実行後、ブラウザで `http://localhost:5173` を開ける
- ローカル Supabase を起動できる

## 1. 事前に確認するもの

- ローカル環境をすべて動かすときは、PC に 7 GB 程度の空きメモリ（RAM）を確保する
- アプリをインストールできる権限を用意する

使用するツールは次のとおりです。

| ツール | このプロジェクトで使うもの |
| --- | --- |
| [Git](https://git-scm.com/install/) | ソースコードと変更履歴の共有 |
| [Node.js](https://nodejs.org/en/download) | **24.18.1** |
| [pnpm](https://pnpm.io/installation) | **11.21.0** |
| [Deno](https://docs.deno.com/runtime/getting_started/installation/) | **2.9.5**。Edge Functionsの検査 |
| [Docker Desktop](https://docs.docker.com/desktop/) | ローカル Supabase の実行 |
| [Visual Studio Code](https://code.visualstudio.com/) | 推奨エディタ。別のエディタでも可 |

## 2. 必要なツールをインストールする

### Windows

1. [Git for Windows](https://git-scm.com/install/windows) をインストールします。迷う項目は初期設定のままで構いません。
2. [Node.js のダウンロードページ](https://nodejs.org/en/download) から **24.18.1** の Windows Installer を選び、インストールします。
3. PowerShell を新しく開き、Node.js と pnpm を準備します。

```powershell
node --version
corepack enable pnpm
corepack install --global pnpm@11.21.0
pnpm --version
git --version
```

`node --version` は `v24.18.1`、`pnpm --version` は `11.21.0` と表示されれば成功です。

4. PowerShellでDenoをインストールし、プロジェクト指定のバージョンに合わせます。

```powershell
irm https://deno.land/install.ps1 | iex
deno upgrade --version 2.9.5
deno --version
```

`deno --version`の先頭が`deno 2.9.5`なら成功です。コマンドが見つからない場合は、PowerShellを閉じて開き直してください。

#### Docker Desktop と WSL 2

この手順では、Windows の Docker Desktop を WSL 2 という仕組みで動かします。最初に次を確認してください。

- Windows Update を実行し、対応中の Windows 10 または Windows 11 にする
- PC に 8 GB 以上の RAM があることを確認する
- タスクマネージャーの「パフォーマンス → CPU」で「仮想化: 有効」になっていることを確認する
- 無効の場合は、PC の BIOS / UEFI で仮想化を有効にする。設定方法は機種ごとに異なるため、分からなければチームメンバーに相談する

5. PowerShell で WSL の状態を確認します。

```powershell
wsl --version
```

バージョン情報が表示された場合は、次のコマンドで更新します。

```powershell
wsl --update
```

`wsl --version` でバージョン情報が表示されない場合は、PowerShell を**管理者として実行**し、次を実行してから PC を再起動します。

```powershell
wsl --install
```

再起動後に Ubuntu の初期設定が表示された場合は、画面に従ってユーザー名とパスワードを作ります。パスワード入力中は文字が表示されませんが、そのまま入力できます。

通常の PowerShell で `wsl --update` と `wsl --version` を実行します。WSL は **2.1.5 以上**が必要です。

6. [Docker Desktop for Windows](https://docs.docker.com/desktop/setup/install/windows-install/) をインストールします。通常は推奨されている「個人ユーザー向け」と **WSL 2** の構成を選びます。
7. Docker Desktop を起動します。Settings の General に項目がある場合は、`Use WSL 2 based engine` が有効になっていることを確認します。
8. Docker Desktop の起動完了後に確認します。

```powershell
docker --version
docker info
```

### macOS

1. ターミナルで Git を確認します。

```bash
git --version
```

開発者ツールのインストール画面が表示された場合は、案内に従ってインストールしてから、もう一度実行します。

2. [Node.js のダウンロードページ](https://nodejs.org/en/download) から **24.18.1** の macOS Installer を選び、インストールします。
3. ターミナルを新しく開き、Node.js と pnpm を準備します。

```bash
node --version
corepack enable pnpm
corepack install --global pnpm@11.21.0
pnpm --version
```

`node --version` は `v24.18.1`、`pnpm --version` は `11.21.0` と表示されれば成功です。

すでに nvm で複数の Node.js を管理している場合、Node.js 24.18.1 をインストール済みでも、開いているターミナルで別のバージョンが選択されていることがあります。`node --version` が `v24.18.1` 以外なら、次のように切り替えます。nvm を使っていない場合、この操作は不要です。

```bash
nvm install 24.18.1 # Node.js 24.18.1 が未インストールの場合のみ
nvm use 24.18.1
node --version
```

4. Denoをインストールします。

```bash
curl -fsSL https://deno.land/install.sh | sh
```

インストール後にターミナルを閉じて開き直し、プロジェクト指定のバージョンに合わせます。

```bash
deno upgrade --version 2.9.5
deno --version
```

`deno --version`の先頭が`deno 2.9.5`なら成功です。

5. [Docker Desktop for Mac](https://docs.docker.com/desktop/setup/install/mac-install/) から、自分の Mac のチップに合うものをインストールします。チップは「Apple メニュー → この Mac について」で確認できます。
6. Docker Desktop を起動し、起動完了後に確認します。

```bash
docker --version
docker info
```

## 3. リポジトリをダウンロードする

### Windows（PowerShell）

```powershell
New-Item -ItemType Directory -Force "$HOME\Developer" | Out-Null
Set-Location "$HOME\Developer"
git clone https://github.com/t161121t/watnow-team-dokidoki.git
Set-Location .\watnow-team-dokidoki
```

### macOS（ターミナル）

```bash
mkdir -p ~/Developer
cd ~/Developer
git clone https://github.com/t161121t/watnow-team-dokidoki.git
cd watnow-team-dokidoki
```

## 4. プロジェクトを初期設定する

Docker Desktop が起動していることを確認し、リポジトリのフォルダで実行します。

```bash
pnpm env:check
pnpm install --frozen-lockfile
```

環境変数ファイルを作ります。

Windows（PowerShell）:

```powershell
Copy-Item .env.example .env.development.local
```

macOS（ターミナル）:

```bash
cp .env.example .env.development.local
```

続いて、ローカル Supabase を起動します。初回は必要なデータのダウンロードに数分かかることがあります。

```bash
pnpm supabase:start
pnpm supabase:status
```

`pnpm supabase:status` に表示された値を `.env.development.local` に設定します。

```dotenv
VITE_SUPABASE_URL=http://127.0.0.1:54321
VITE_SUPABASE_PUBLISHABLE_KEY=ここにPublishable keyを貼り付ける
```

- `VITE_SUPABASE_URL` には `Project URL` または `API URL` を使う
- `VITE_SUPABASE_PUBLISHABLE_KEY` には `Publishable key` を使う
- `Secret key` や `service_role key` は絶対に設定・共有しない
- `.env.development.local` は Git に追加しない

最後に、コードが正しく動く状態か確認します。

```bash
pnpm verify
pnpm dev
```

ブラウザで `http://localhost:5173` を開きます。開発サーバーを止めるときは、実行中のターミナルで `Ctrl + C` を押します。その日の作業を終えるときは、Supabase も止めます。

```bash
pnpm supabase:stop
```

## 5. よくある問題

| 症状 | 対応 |
| --- | --- |
| `node`、`pnpm`、`deno`、`git` が見つからない | ターミナルをすべて閉じて開き直す。直らなければインストールを確認する |
| `Unsupported environment (bad pnpm and/or Node.js version)` と表示される | `node --version` と `pnpm --version` を確認する。macOS で nvm を使っている場合、Node.js が `v24.18.1` 以外なら `nvm use 24.18.1` で切り替える |
| `pnpm env:check` でバージョンエラー | Node.js 24.18.1、pnpm 11.21.0、Deno 2.9.5になっているか確認する |
| Windows で PowerShell のスクリプト実行エラー | `pnpm` の代わりに `pnpm.cmd` を使うか、コマンドプロンプトを使う |
| `wsl --version` でバージョンが表示されない | 管理者 PowerShell で `wsl --install` または `wsl --update` を実行し、PC を再起動する |
| Docker が仮想化のエラーで起動しない | タスクマネージャーで仮想化を確認し、無効なら BIOS / UEFI の設定を確認する |
| Docker に接続できない | Docker Desktop を起動し、`docker info` が成功するまで待つ |
| `pnpm supabase:start` が失敗する | Docker Desktop の起動とエラーに表示されたポートを確認する。分からなければエラー全文をチームに共有する |
| 環境変数を変えても反映されない | `Ctrl + C` で `pnpm dev` を止め、もう一度起動する |

`.env.development.local`、パスワード、実際の秘密情報は Git に追加したり、チャットに貼ったりしないでください。
