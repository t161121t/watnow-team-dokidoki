## 2. 今回「変わった / 追加した」こと

### 2.1 プロダクト方針

| 項目 | 以前（ドラフト） | 今回 |
| --- | --- | --- |
| 秘密の獲得手段 | ショップ即買 **または** オークション | **オークションのみ**（ショップ廃止） |
| オークションの役割 | 入札者中心（進行役の記述は薄い） | **入札者 / 出品者 / ディーラー** を明示 |
| 出品 | 登録≒出品に近い記述もあった | **登録 ≠ 出品**。出品実施後に開催待ち |
| 出品者報酬 | 落札時の消費中心の記述 | 出品時にポイント振込 → 落札で追加割合 → 不落札で没収（マイナス可） |
| 入札の見え方 | 匿名 / 記名を設定で切替、という案 | **出品者は入札者を知る / それ以外は知らない** |
| 落札ポイントの行方 | 主に落札者の消費 | **ディーラーと出品者で按分** |
| 同時開催 | 並列の言及あり | **1 グループで複数競り可**、競りごとにディーラー割当 |

### 2.2 ドキュメント構成

| 操作 | パス | 内容 |

## 3. 今回「残す」もの（継続方針）

実装・仕様判断の前提として、**これまで通り有効**なもの。

- 仲のいい友達グループ向けコミュニケーションゲーム、というコンセプト骨子
- 本人が公開してよい秘密のみ扱う
- ポイント・秘密・オークションは**グループ単位で完全独立**
- ミニゲーム / チャレンジでポイントを稼ぐ流れ
- アカウント・グループ管理（作成・招待・幹事など）の大枠
- 技術スタック方針（React PWA + Supabase、RLS、整合は PostgreSQL Function など）
- `docs/概要まとめる.md` の背景・課題・価値・「なぜオークションか」の文章
