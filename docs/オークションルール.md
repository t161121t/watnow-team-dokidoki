## 1. 役割

| 役割 | 別名 | 説明 |
| --- | --- | --- |
| 入札者 | 秘密の買い手 | ポイントで入札し、落札すれば秘密を閲覧できる |
| 出品者 | 秘密の売り手 | 秘密を登録・出品し、出品・落札に応じてポイントを得る |
| 主催者 | オークションディーラー | 競りごとにランダム選抜。進行役。自身は入札不可 |

1 つの競りにおいて、同一ユーザーが複数役割を兼ねることはない（出品者 ≠ ディーラー、ディーラーは入札不可）。

## 2. 秘密の出品フロー

### 2.1 競り前

1. **登録**  
   出品者は任意の秘密を登録できる。
2. **価格の自己設定と妥当性チェック**  
   新規登録時、出品者が決めた額で秘密を登録する。  
   額と内容が見合っているかは、AI 等による validation を想定する。
3. **登録 ≠ 出品**  
   登録した段階ではまだオークションには出ない（在庫・下書き扱い）。
4. **出品の実施**  
   出品を実施すると、**一定期間後**にオークション開催となる。  
   開催時（または出品確定時）、当該相当のポイントが出品者に振り込まれる。

### 2.2 競り後

5. **落札時の追加報酬**  
   競り完了（落札）後、落札価格の**一定割合**が追加で出品者に振り込まれる。
6. **不落札時の返却**  
   落札されなかった場合、「価値のない秘密」とみなし、本来価格より**目減りした秘密**が、出品前ステータスで返却される。
7. **不落札時のポイント没収**  
   6 の場合、4 で一度振り込まれたポイントは没収される。  
   残高が足りない場合は**借金（マイナス残高）**になり得る。

### 2.3 秘密ステータス（案）

```text
registered（登録済み・未出品）
  → listed / pending_auction（出品実施・開催待ち）
  → on_auction（競り中）
  → sold（落札）
  → returned（不落札・目減りして登録済みへ戻る）
```

## 3. オークション（テーブル）ルール

### 3.1 開催単位

- オークションテーブル（競りの場）は**グループ単位**と一致する。
- 出品が確認されたら、**一定期間経過後**にオークションが開催される。
- 開始価格は**出品価格以上の一定額**から始まる。
- 開催後、**一定期間**オープン（入札可能）な状態になる。
- 1 グループで**同時に複数の競り**を開催できる。
- 競りごとにディーラーがランダムに割り当てられる。

### 3.2 参加資格

| 対象 | 入札 | 備考 |
| --- | --- | --- |
| グループメンバー（出品者含む） | 可 | 出品者も自グループの他競り等への参加は可（自出品への入札可否は未決） |
| ディーラー（当該競り） | 不可 | 進行役のため入札できない |

### 3.3 入札の可視性（情報非対称）

- **出品者**は、誰が入札したか分かる。
- **入札者以外**（他の参加者・傍観者）は、誰が入札したか分からない。
- ディーラーが入札者を把握できるかは未決（進行に必要なら限定公開を検討）。

### 3.4 入札価格の分配

- 入札（落札）で動いたポイントは、**ディーラーと出品者で按分**する。
- 按分割合は未確定パラメータ（下記参照）。

## 4. ディーラー

### 4.1 選抜

- 出品者**以外**のグループメンバーから、ランダムにディーラーを選抜する。
- 競りごとに独立して割り当てる（同時開催時は競りごとに別ディーラーになり得る）。

### 4.2 権限・見える情報

- ディーラーは、**出品者**と**売りに出された秘密の概要**を把握できる。
- **本文（中身）は見られない**。

### 4.3 役割

- 秘密の概要から、「誰の・何に関する秘密か」を参加者に説明し、競りを盛り上げ・加速させる。
- 自身は当該競りに入札できない。

### 4.4 辞退（案）

- 割り当てられたディーラーは、**一定ポイントを支払うことで辞退**できる。
- 辞退料の目的は、進行役の負担を軽減しつつ、安易な辞退を抑えること。
- 辞退後は、残りのグループメンバーから**別のディーラーを再割当**する（再選抜のタイミング・回数上限は未決）。
- 競り開始後の辞退可否、辞退料の行き先（没収 / グループプール等）も未決。

## 5. 未確定パラメータ（実装前に決める）

機能要件・定数への落とし込み前に合意が必要な項目。

| ID | 項目 | メモ |
| --- | --- | --- |
| P1 | 出品実施〜開催までの待機時間 | 「一定期間」 |
| P2 | オークション開放時間 | 「一定期間オープン」 |
| P3 | 開始価格の決め方 | 出品価格以上の「一定額」（加算固定 / 倍率など） |
| P4 | 出品時の前払いポイント額 | 「当該相当」の定義（出品価格と同額？） |
| P5 | 落札時の追加振込割合 | 落札価格の「一定割合」 |
| P6 | 不落札時の秘密の目減り率 | 返却時の価値低下 |
| P7 | 入札額のディーラー / 出品者按分比 | 例: 3:7 など |
| P8 | 出品者の自出品への入札可否 | 参加可とあるが自出品は除外が自然か |
| P9 | ディーラーへの入札者開示 | 進行に必要か |
| P10 | 額と内容の AI validation 基準 | モデル・閾値・手動オーバーライド |
| P11 | マイナス残高の上限・返済ルール | 借金の扱い |
| P12 | ディーラー辞退料 | 固定額 / 出品価格の割合など。競り開始前後の可否、再割当ルール、辞退料の行き先 |

## 6. プロダクト方針メモ

### 6.1 ショップ機能は廃止

- **ショップ（固定価格での即時購入）は設けない。**
- 秘密の獲得手段はオークション（本ルール）に一本化する。
- 既存の `docs/機能要件.md` §6・画面のショップ記載は旧案として残すが、実装対象外。

## 8. 不変条件（既存方針との接続）

- ポイント・秘密・オークションは**グループ完全分離**（他グループへ漏れない）。
- 扱う秘密は**本人が公開してよい内容のみ**。
- 入札・ウォレット増減・按分は、レースや二重払いを防ぐため PostgreSQL Function 等での整合を前提とする（`docs/技術選定.md`）。
